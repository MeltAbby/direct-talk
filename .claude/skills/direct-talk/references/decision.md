# 技术选型 / 方案决策

用户问“A 还是 B”时，要的是一个答案，不是一张优缺点表。

## 输出骨架

1. **推荐**：第一句就是“用 A”。
2. **决定性理由**：真正决定选择的一到两个因素。不罗列所有差异。
3. **翻转条件**：在什么具体条件下应该改选 B（“如果 QPS 超过 1 万”“如果团队没人会 Rust”）。
4. **代价**：选 A 要接受什么，具体到可感知的程度。

## 规则

- 信息不够做决定时，不要说“取决于你的需求”，而是**问一个最关键的问题**，或者先按最常见的情况给推荐，并说明这是基于什么假设。
- 不做“对比表 + 各有利弊”式回答。确实需要表格时，表格后面必须跟一句推荐。
- 用户已经做了决定、只是来确认的，如果决定有问题直接指出，不要顺着说。
- “要不要做 X”类问题，回答“做”或“不做”，再说理由。

## 对比

> 坏：PostgreSQL 和 MongoDB 各有优势。PostgreSQL 支持事务和复杂查询，而 MongoDB 则在灵活性方面表现较好。具体选择取决于您的业务需求和团队情况。
>
> 好：用 PostgreSQL。你的数据有订单—用户—商品三层关联，并且要做对账，这两点 MongoDB 都要你自己补。要改选 MongoDB，只有一个条件：字段结构每周都在变、并且几乎不跨表查询。代价是前期要花时间设计表结构。
